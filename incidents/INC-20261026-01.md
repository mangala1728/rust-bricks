# 缺陷通報：ISO 14443 CRC-A / CRC-B 計算錯誤

## 1. 發現情境與影響
src/nfc_iso14443_ndef.rs:12-24。中間變數 `ch` 宣告為 u16，`ch ^ (ch << 4)` 後未截回 8 bit（ISO/IEC 14443-3 Annex B 參考實作中 ch 為 unsigned char），高位元污染 `ch<<3` 與 `ch>>4`。所有與真實 NFC 卡片的 CRC 互通都會失敗。現有測試只用 `assert_ne!(crc, 0x6363)`，無法偵測。

## 2. 最小重現代碼（Reproduction Snippet）
```rust
let mut c: u16 = 0x6363;
for b in b"123456789" { nfc_iso14443_ndef::nfc_iso14443a_crc_step(*b, &mut c); }
assert_eq!(c, 0xBF05); // 實得 0x66FD
assert_eq!(nfc_iso14443_ndef::nfc_iso14443b_crc_calculate(b"123456789"), 0x906E); // 實得 0x15DB
```
（已於 commit 2a66ba7、`--target x86_64-unknown-linux-gnu` 實際執行重現）

## 3. 預期行為 vs 實際行為
- **預期**：CRC-A("123456789") 應為 0xBF05、CRC-B 應為 0x906E（CRC-16/ISO-IEC-14443-3-A、CRC-16/X-25 標準檢查值）
- **實際**：0x66FD / 0x15DB

## 4. 排障日誌與修復方案（由工兵填寫）
建議方向：將 `ch` 改為 u8：`let mut ch = byte ^ (*crc as u8); ch ^= ch << 4; let ch = ch as u16;`

**修復**（commit `65fa457`，分支 `worker/review-2026-10-26`）：`ch` 改為 u8 運算並截回 8 位元；CRC-B 重用 CRC-A step。測試改用標準檢查值 0xBF05 / 0x906E / REQB 0xFF71。

迴歸測試：`tests/all_bricks.rs`（Red → Green）。
