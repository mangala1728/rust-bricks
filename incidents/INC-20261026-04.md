# 缺陷通報：查詢字串超過 6 字元時永遠判定匹配

## 1. 發現情境與影響
src/text_cleaner.rs:95。`levenshtein_distance_bounded(query, &t_sub, 2)` 在距離 > 2 時回傳上限 2；而長度 > 6 的門檻是 `dist <= 2`，因此恆為 true。

## 2. 最小重現代碼（Reproduction Snippet）
```rust
assert!(!text_cleaner::fuzzy_prefix_match("abcdefgh", "zzzzzzzz")); // 實得 true
```
（已於 commit 2a66ba7、`--target x86_64-unknown-linux-gnu` 實際執行重現）

## 3. 預期行為 vs 實際行為
- **預期**：編輯距離 8，應回傳 false
- **實際**：true

## 4. 排障日誌與修復方案（由工兵填寫）
建議方向：以 max_dist = 門檻 + 1 呼叫，或讓 bounded 函式在超過上限時回傳 max_dist + 1。

**修復**（commit `65fa457`，分支 `worker/review-2026-10-26`）：以 `threshold + 1` 為 bounded 上限呼叫，使「超過門檻」可被分辨；新增長查詢不匹配測試。
