# 缺陷通報：強制 Windows build target 導致 Linux/CI 與 guard 無法編譯

## 1. 發現情境與影響
.cargo/config.toml 設定 `[build] target = "x86_64-pc-windows-gnullvm"`。在 ubuntu-latest 的 GitHub Actions（只安裝 host target）與任何 Linux/macOS 環境，`cargo test` / `cargo run` 皆以 E0463 失敗；`guard` 內部呼叫的 `cargo test` 也因此失敗。CI 實質上無法驗證任何提交。

## 2. 最小重現代碼（Reproduction Snippet）
```bash
# 在 Linux 上：
cargo test        # error[E0463]: can't find crate for `std` (x86_64-pc-windows-gnullvm)
cargo test --target x86_64-unknown-linux-gnu   # 100 passed
```
（已於 commit 2a66ba7、`--target x86_64-unknown-linux-gnu` 實際執行重現）

## 3. 預期行為 vs 實際行為
- **預期**：CI 與 guard 在任意平台可編譯並執行
- **實際**：E0463 編譯失敗

## 4. 排障日誌與修復方案（由工兵填寫）
建議方向：移除 config.toml 的 [build] target（改由 Windows 本機自行設定環境變數或 `--target`），或在 CI 安裝該 target 並以 host target 執行測試。

**修復**（commit `65fa457`，分支 `worker/review-2026-10-26`）：移除倉庫層級 `[build] target`，改以註解說明 Windows 本機可用 `CARGO_BUILD_TARGET` 或使用者層級設定。

迴歸測試：`tests/all_bricks.rs`（Red → Green）。
