# 量測系統分析（MSA）：高風險積木的「先驗量具、再驗產品」

本文件寫給不看程式的管理者：只說流程、判讀規則和報告怎麼讀。

## 為什麼要有
測試（量具）如果和產品出自同一個錯誤，產品會「通過自己的考卷」。INC-20261105-01（CAN-FD CRC）就是這樣：規格答案照錯的演算法推出，CI 全綠，產品卻是錯的。

## 角色分工（職責分離）
| 誰 | 做什麼 | 不准做什麼 |
|---|---|---|
| 外部公開來源 | 提供公認正確值（標準件），例如 RevEng CRC 目錄 | — |
| 量具製作者 | `msa/<模組>.rs`：參考實作、標準件、挑戰件 | 不准寫產品 |
| 雲端農夫 | 依規格生產 `src/<模組>.rs` | 看不到盲測輸入 |
| CI | 自動判讀、出紅黃綠報告 | — |

## 判讀規則（照 IATF 16949 MSA 精神，門檻依軟體調整）
1. **標準件**沒過 → 🔴 **量具壞了**。產品不量測，農夫拒絕開工。
2. **挑戰件**（已知錯誤寫法）的抓出率：≥ 90% 🟢；70–90% 🟡 需簽核；< 70% 🔴 量具重做。
3. **容差比**（測試允許誤差 ÷ 預期值，相當於 P/T）：< 10% 🟢；10–30% 🟡；> 30% 🔴。
4. 量具可信時才量產品：黃金向量全過，而且**盲測**（規格裡沒有的隨機輸入，與參考實作比對）0 不一致 → 🟢 允收；否則 🔴 拒收。
5. **重現性**：Linux x86、Windows、Linux ARM 三平台結果必須一致（CI 矩陣）。

## 報告在哪裡看
GitHub → Actions → CI 執行紀錄 → 「MSA Gauge R&R」工作的 Summary。表格每一列是一個高風險模組；任一 🔴 會讓 CI 變紅。

## 適用範圍
目前試點：`canfd_crc`。其他積木要納入時，新增 `msa/<模組>.rs`，帶入標準件、挑戰件和 `@msa-blind`，CI 會自動產生量具測試。
