# 跨語言演算法轉譯與差分異變驗證方法論（Transpilation Methodology）

> **核心準則**：不迷信外部黑箱庫，以「逆向推理 ＋ 純手刻轉譯 ＋ 雙向差分測試 ＋ 邊界型別異變」四步閉環，打造最高品質零依賴 Rust 微積木。

---

## 1. 四步攻堅標準作業程序（4-Step Transpilation Protocol）

```text
┌────────────────────────────────────────────────────────┐
│ 1. 深度研讀子函式庫（Source Dissection）              │
│    • 查閱 Python/C++/TS/Kotlin 官方子庫或 RFC 規範      │
│    • 剝離巨型框架，提煉最小數學公式與狀態轉換邏輯      │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│ 2. 手刻純 Rust 零依賴微積木（Cleanroom Rust）          │
│    • 純記憶體、零外部 crate、狀態窮舉、NASA JPL 60 行  │
│    • 06/09 號合約：@outputs、@domain 第一行剛性守衛    │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│ 3. 雙向差分測試（Differential Parity Verification）     │
│    • 執行原語言測試向量，擷取二進位或數值真值          │
│    • Rust 單元測試一對一比對，達成 100% 位元級吻合     │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│ 4. 邊界型別異變壓測（Boundary & Type Mutation）        │
│    • 異變輸入邊界：8-bit 變 16-bit、極限溢出、符號翻轉 │
│    • 比對兩者反應：若不符則修改代碼或記錄邊界安全備註  │
└────────────────────────────────────────────────────────┘
```

## 2. 實戰示範案例：CRC32 / Adler-32 校驗微積木

### 步驟 1：原語言子函式庫推理（Python `zlib` / RFC 1952）
- **CRC-32**：生成多項式為反轉 IEEE 802.3 `0xEDB88320`，初值全 1，結尾取反。
- **Adler-32**：質數模數 `65521`，初始 $s_1=1, s_2=0$。每 5552 個位元組執行一次取模避免 32 位元溢出。

### 步驟 2：手刻純 Rust 零依賴轉譯（[`src/packet_checksum.rs`](../src/packet_checksum.rs)）
- 使用 `const fn` 在編譯期生成 256 項查表，執行期零 Heap 配置。
- 每函式長度控制在 5～25 行，嚴格符合 JPL 60 行規範。

### 步驟 3：雙向差分測試客觀評分
| 測試項目 | 原語言（Python `zlib`）真值 | Rust `packet_checksum` | 差分比對判定 |
|---|---|---|---|
| `CRC32(b"")` | `0x00000000` | `0x00000000` | ✅ 100% 吻合 |
| `CRC32(b"123456789")` | `0xcbf43926` | `0xcbf43926` | ✅ 100% 吻合 |
| `Adler32(b"")` | `0x00000001` | `0x00000001` | ✅ 100% 吻合 |
| `Adler32(b"123456789")` | `0x091e01de` | `0x091e01de` | ✅ 100% 吻合 |
| 增量流式更新 | `update(part1) + update(part2)` | 一致 | ✅ 狀態累加無損 |

### 步驟 4：邊界條件與 8-bit $\rightarrow$ 16-bit 型別異變
- **異變情境**：Android 手機麥克風音訊（PCM16）與感測器暫存器為 16 位元有號整數 `[-1, 0, 1, 32767, -32768]`。
- **傳統做法痛點**：原語言通常需經由序列化（`struct.pack` 或 `ByteBuffer`）分配額外記憶體轉為 8-bit byte array，產生 GC 負擔與拷貝開銷。
- **Rust 微積木革新**：手刻 `crc32_pcm16_le` 與 `adler32_pcm16_le`，直接以暫存器解包高低位元組並流式運算。
- **異變對齊結果**：
  - Python `struct.pack('<5h', *pcm)` 之 CRC32 為 `0xecceca30` $\rightarrow$ Rust `crc32_pcm16_le` 精確產出 `0xecce_ca30`。
  - Python `struct.pack('<5h', *pcm)` 之 Adler32 為 `0x18f603fe` $\rightarrow$ Rust `adler32_pcm16_le` 精確產出 `0x18f6_03fe`。
- **結論**：16-bit 異變與 8-bit 序列化結果達成 100% 恆等對齊，且零記憶體分配！
